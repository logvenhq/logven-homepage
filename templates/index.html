One model of the company, built from three parts

Everything in Logven is made of sheets, workers and models. Together they turn the way a team already works into software the whole company can read, run and improve.

Sheets The state

Everything the company knows, as typed, structured records. One shared source instead of copies across files and versions.

Workers The functions

Code that AI writes from how your team works. Each worker is approved before it runs, then runs the same way every time.

Models The overview

A living model of the whole company, assembled from the work as it happens. For the first time, an organisation can be seen, and reasoned about, as a system.

How a pilot works

Workers, written by AI and run as code

A worker is a short program. AI writes it from how the team describes the work, a person approves it, and from then on it runs the same way every time.

Approved before it runs
Approval is bound to the exact code and its permissions.
Isolated
Each run executes in a sandbox, with no way out except the sheets and tools it was granted.
Logged
Every call to a sheet or to AI is recorded and can be traced.
Revisioned
Changing a worker creates a new revision and a new approval.

The right model for each step

Where a step needs judgement, the worker calls the right kind of model: a time-series model to forecast, a vision model to read a photo, a language model to write. Each call declares the shape of its answer, so the rest of the code works with data it can trust.

Typed answers
Every call states its output shape, and the answer has to match it.
Checked before approval
Checks run against real sheets, with AI answers replaced by placeholders.
On your hardware
Calls go to models running inside your organisation.
Only where needed
Everything that can be plain code stays plain code.

Complex technical work, made simple

Logven brings the right kind of AI to each step of a process, from language and vision to time series and decisions. All of it runs on your own hardware, so your data never leaves the building.

  • Language.Reports, emails, specs.

    Language models that read and write the paperwork

    Turn emails, reports and specifications into structured data, and draft the documents that go back out.

  • Vision.Scans, drawings, inspections.

    Vision models for documents and the field

    Read scanned forms, tables and technical drawings, and check inspection photos against what the process expects.

  • Time series.Sensors, trends, anomalies.

    Time-series models for plant and sensor data

    Forecast load and demand, catch anomalies in readings, and flag drift long before it shows up in a report.

  • Decisions.Plans, schedules, what-ifs.

    Predictive models that help decide

    JEPA-style world models learn how a process behaves, so Logven can compare scenarios and propose a next step for a person to approve.

  • Retrieval.Every document, findable.

    Search across everything the company knows

    Embedding models index documents, records and past runs, so every answer points back to its source.
